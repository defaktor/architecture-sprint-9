# FURPS+ таблица требований (MVP открытия депозитов)

| Код   | Категория         | Требование                                                                                   | Комментарий                                                                                           |
|--------|-------------------|----------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------|
| F1     | Functionality      | Возможность подачи заявки на депозит с сайта                                                  | Требует интеграции сайта с системой кол-центра                                                        |
| F2     | Functionality      | Возможность подачи заявки на депозит в интернет-банке                                        | Требует интеграции ИБ с системой обработки ставок (возможно, через прослойку между ИБ и АБС)          |
| F3     | Functionality      | Персонализированные ставки в интернет-банке                                                  | Требуется модуль расчёта и хранения ставок, доступный для кредитного и депозитного бэк-офиса          |
| F4     | Functionality      | Подтверждение заявки в интернет-банке через СМС-код                                          | Требует интеграции с СМС-шлюзом (без участия подрядчика интернет-банка)                              |
| F5     | Functionality      | Передача информации в АБС для окончательной обработки заявки                                 | Важно реализовать через прослойку, чтобы не нагружать БД АБС                                          |
| F6     | Functionality      | Уведомление клиента СМС о принятии ставки и открытии депозита                               | Необходимо централизованное управление уведомлениями                                                  |
| U1     | Usability          | Совместимость дизайна сайта и ИБ с фирменным стилем                                          | Поддержка принятого UI-kit                                                                            |
| U2     | Usability          | Быстрая работа интерфейса (до 1 сек отклика)                                                 | Возможна оптимизация справочников и API-интерфейсов                                                   |
| U3     | Usability          | Простой и понятный процесс подачи заявки                                                     | Особенно важен для сайта — взаимодействие с новым, «холодным» пользователем                           |
| R1     | Reliability        | Доступность ИБ и сайта — 99.9%                                                               | Нужен план отказоустойчивости, резервный ЦОД                                                          |
| R2     | Reliability        | Работа сервисов 24/7                                                                         | Возможен перенос части логики из АБС в промежуточный сервис                                           |
| R3     | Reliability        | Нельзя перегружать базу данных АБС                                                           | Необходимо разделение нагрузки — кэширование ставок, буферизация данных                              |
| P1     | Performance        | Задержка отклика интерфейсов < 1 секунды                                                     | Возможна оптимизация фронта/бэка, кэширование                                                         |
| P2     | Performance        | Горизонтальное масштабирование компонентов                                                   | Применимо к сервисам сайта и ИБ; АБС масштабируется только вертикально                                |
| S1     | Supportability     | Возможность поддержки существующими командами                                                | Требует переиспользования стека: .NET Framework, Java, React, MS SQL, Oracle                         |
| S2     | Supportability     | Реализация СМС-функционала без подрядчика интернет-банка                                     | Использовать внутренний СМС-шлюз                                                                      |
| S3     | Supportability     | Документирование API и бизнес-логики                                                         | Нужно для последующей автоматизации открытия депозита                                                |
| +R1    | Restrictions       | Использовать технологии, уже применяемые в банке                                             | Java, .NET, React, PostgreSQL, MS SQL, Oracle, Kafka                                                  |
| +R2    | Restrictions       | Нельзя напрямую вызывать АБС из интернет-банка                                               | Необходимо промежуточное API или очередь                                                             |
| +R3    | Restrictions       | XLS-файлы ставок остаются источником истины в MVP                                            | Требуется интеграция через модуль загрузки/чтения                                                     |
| +R4    | Restrictions       | СМС-логика не должна требовать обновлений ядра ИБ                                            | Реализация через выделенный внутренний сервис                                                         |
| +R5    | Restrictions       | Сайт передаёт персональные данные — трафик должен быть зашифрован                           | HTTPS, возможен TLS-пиннинг                                                                          |
| +R6    | Restrictions       | Kafka пока не используется в интернет-банке                                                  | Использовать как потенциальное развитие при переходе на микросервисы                                 |
| +R7    | Restrictions       | Интернет-банк — монолит, сложно масштабировать                                               | Подумать о выносе новых функций (депозиты) в отдельный сервис                                        |

## Дополнительные архитектурно-значимые требования (с обоснованием)

| Код    | Требование                                                                                   | Обоснование                                                                                          |
|--------|----------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------|
| **U2** | Быстрая работа интерфейса (до 1 сек отклика)                                                 | Не было явно сформулировано, но вытекает из жалоб на производительность и ожидания удобства.         |
| **S3** | Документирование API и бизнес-логики                                                         | Не упоминалось напрямую, но обязательно для масштабируемости, поддержки и последующей автоматизации. |
| **+R5**| Сайт передаёт персональные данные — трафик должен быть зашифрован                            | Требование логично, но явно сформулировано только по сайту — не упоминался TLS или HTTPS напрямую.   |
| **+R6**| Kafka пока не используется в интернет-банке                                                  | Это не ограничение от бизнеса, а техническая реальность — важно зафиксировать для архитектурных решений. |
| **+R7**| Интернет-банк — монолит, сложно масштабировать                                               | Не указано явно в задании, но критично, если думать про вынос функционала открытия депозита в сервис. |
